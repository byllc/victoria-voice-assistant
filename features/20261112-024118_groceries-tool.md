## Blocking decisions

None. Settled 2026-11-12: all six as proposed (Bill: "Yes, accept all six").

1. **How it's configured.** Proposal: a tool entry like any other, `kind: builtin`, `service: reminders.list`, with the list in the tool's own settings (`list: Victoria Groceries`). More list tools later (Hardware, Costco) are more entries. The tool works with or without the general `reminders` tool, but needs Reminders access the same way.
2. **What checked and unchecked mean.** Proposal: the list keeps every item. **Unchecked means we need it**, and checked means we have it. So:
   - "We're out of pizza": unchecks Pizza, or adds it when it isn't on the list.
   - "We got the milk" or "bought the milk": checks it.
   - "Do we need carrots?": yes if Carrots is unchecked; no if it's checked or not on the list ("not on the list").
3. **What "remove" does.** You asked for remove, and the Reminders tool never deletes (its decision 5: a misheard "delete" can't be undone). Proposal: on this tool only, "take X off the list" deletes the item. A lost grocery item costs little, and it's what removing means on a shopping list. The alternative is that remove only checks the item, so nothing is ever deleted.
4. **What the model is given.** Proposal: for a question, the tool returns every item, as "need" (unchecked) or "have" (checked), and the model answers in a sentence or two ("Yes, carrots are on the list."). The list is read fresh each time, so it's never out of date (`forget_after_s: 0`). For add, out of, got and remove, the tool answers itself with no second model call ("I've added Ice cream to Victoria Groceries."), as the Reminders tool does now.
5. **Matching item names.** Proposal: the same forgiving matching as list names. Case, plurals and small misspellings don't matter ("carrot" finds Carrots, "icecream" finds Ice cream). When two items fit about equally, it asks which. A new item keeps the words as said, capitalised ("Ice cream").
6. **Who can use it.** Proposal: any household device, like the Reminders tool.

## Notes

- Builds on the [Reminders tool](20261111-185146_apple-reminders-tool.md) (EventKit, access, list creation). Reading checked items as well as unchecked ones is new: the Reminders tool reads only unchecked ones.
- Big lists: the whole list goes to the model. A grocery list of 50-100 items is a few hundred words, which is fine. A list with years of checked items would be long, so checked items older than 90 days could be left out. That isn't proposed now; we can look at the real Groceries list's size before switching to it.
- No satellites involved, so this is current-phase work.

## Evidence

Built 2026-11-12:

- `service: reminders.list` with `list:` on the tool entry (`ToolConfig.list_name`, written `list:` in YAML). `ListTool` in `tools/reminders.py`. Actions:
  - `read` returns the whole list, `need` (unchecked) and `have` (checked), and the model answers.
  - `need` adds, or unchecks an item checked off before; something already needed is left alone.
  - `got` checks off.
  - `remove` deletes, on this tool only.
- The list is made when the tool loads if Reminders doesn't have it (02:45 UTC: `reminders_list_created`, `status: in iCloud`).
- Replies for need, got and remove are said directly (`ToolOutcome.direct`, a new flag), and questions go to the model (`forget_after_s: 0`, read fresh each time).
- Item matching forgives case, plurals and small misspellings ("carrot", "icecream", "tomatos").
  - Adding needs the item's whole name ("eggs" adds Eggs and leaves Egg noodles alone).
  - Checking off or removing takes part of a name, and asks which when two fit ("onions": Red or White?).
  - The same item twice ("Milk", "milk") counts as one.
- Several items at once, comma-separated ("carrots, milk and pizza"), each handled and said together: "I've added “Bread”, “Butter” and “Coffee” to Victoria Groceries."
- EventKit: reading checked items (`predicateForRemindersInCalendars_`), unchecking, removing (`removeReminder_commit_error_`).
