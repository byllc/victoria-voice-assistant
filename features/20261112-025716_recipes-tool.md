## Blocking decisions

None open. All eight below accepted as proposed (Bill, 2026-11-12: "Yes, accept all eight"). Settled earlier the same day: recipes live in a folder, written to a template; web search is used when no recipe in the folder is similar to what was asked.

1. **Where the folder is.** Proposal: `recipes/` next to the database (`~/Library/Application Support/Victoria Voice Assistant/recipes/`), with the path settable in `tools.yaml` (`recipes.folder`), so it can be an iCloud Drive or shared folder you edit from anywhere. The nightly backup would carry it. It isn't in the repository: recipes are your data, not code.
2. **The template.** Proposal: one Markdown file per recipe, easy to write by hand, `_template.md` in the folder:

   ```markdown
   # Paella
   Serves: 6
   Time: 1 hour 15 minutes
   Tags: dinner, spanish, rice

   ## Ingredients
   - 2 cups bomba rice
   - 1 pinch saffron
   - 1 lb shrimp

   ## Steps
   1. Heat the stock with the saffron.
   2. …

   ## Notes
   Source: https://…
   ```

   Only the title and the Ingredients list are required. A file that doesn't fit the template is skipped and named in the log and in `assistant recipes check`.
3. **What "similar" means.** Proposal: a recipe matches by its title and tags, with the same forgiving matching as list names ("paela" finds Paella; "chicken soup" finds Chicken noodle soup). When two fit about equally, it asks which. When nothing is close, it goes to web search.
4. **Web recipes.** Proposal: search with the search service we already run, read the best recipe page, and answer from its ingredients. Then it asks "Save this to your recipes?", and a yes writes it into the folder in the template, with its source link. It never saves without the yes. In chat, the page also opens in the document panel.
5. **What "have" means.** The grocery list says checked means we have it, but something checked off weeks ago may be gone. Proposal: an ingredient counts as on hand if it's on the grocery list and checked off within the last 14 days (`recipes.have_days`), plus a short list of staples you always have (`recipes.staples`: salt, pepper, oil, water …). Unchecked or absent counts as missing. The alternative is a separate Pantry list.
6. **Missing ingredients.** Proposal: after "what do I need to make paella?", it asks "Add those to groceries?", and a yes adds the missing ones to the grocery list (unchecked). Quantities aren't added, only the item names.
7. **"What can I make?"** Proposal: from the folder only (not the web): the recipes with the fewest missing ingredients, three at most, each with what it's missing ("Paella: you'd need saffron and shrimp"). The model picks from a list the tool has already worked out, so it can't invent a dish.
8. **How much it says.** Proposal: by voice, short: the missing ingredients, or the dish ideas. In chat, the same answer, and "show me the recipe" opens the whole recipe in the document panel. Reading the steps aloud one at a time ("next step") would be a later feature.

## Notes

- Matching ingredients to grocery items is the hard part: "2 cups bomba rice" against "Rice", "1 lb large shrimp, peeled" against "Shrimp". Proposal: the tool strips amounts and preparation words and matches on the main words, with the grocery tool's item matching. It will sometimes be wrong (it may count "rice" as bomba rice), and the answer names the grocery item it matched so you can tell.
- Needs the [groceries tool](20261112-024118_groceries-tool.md) (its list and matching) and the search service.
- No satellites involved, so this is current-phase work.

## Evidence

Built 2026-11-12:

- `tools/recipes.py`:
  - The template (`parse_recipe`, `render_recipe`, `_template.md` written into the folder) and `RecipeBook` (load, find by title or tags with the forgiving matching, save without overwriting). A file that doesn't fit is skipped, logged (`recipe_skipped`) and listed by `assistant recipes check`.
  - `ingredient_name` strips amounts, units and preparation words ("1 lb large shrimp, peeled" → "shrimp").
  - "Have": grocery items checked off within `have_days` cover an ingredient when every word of the item is in it ("Rice" covers "bomba rice"; "Egg noodles" doesn't cover "eggs"). Staples match only the same thing, give or take a plain describer ("black pepper", "kosher salt"; not red bell pepper).
  - Web: `recipe_from_html` reads a page's schema.org Recipe data, tried on the first 4 search results (`PageReader.html`, public addresses only).
  - Actions: `need`, `suggest`, `show`, `save`, and `add_missing` (run by a yes).
- `RecipesConfig` (`recipes:` in `tools.yaml`): `folder`, `groceries_tool`, `have_days` (14), `staples`. The `recipes` tool in both `tools.yaml` files. A stub when the groceries tool or Reminders access is missing.
- Grocery items carry when they were checked off (`ReminderItem.completed_at`, EventKit's completion date).
- The nightly backup carries `recipes/` next to the database and restore puts it back; a folder set elsewhere in config is not backed up by us.
- `assistant recipes check`. Docs: `docs/recipes.md`, architecture §8.
- Tests: `tests/test_recipes.py` (28). `uv run pytest -q`: 547 passed, 3 skipped.

Two things differ from the proposals as written:

- Decision 8, "show me the recipe": the whole recipe appears as a card in the chat, not in the document panel, which only opens web addresses. A web recipe's card has its source link, which opens in the panel.
- Decision 4, saving a web recipe: when ingredients are missing, the question after the answer is "Add those to groceries?"; the save question ("Save this recipe to your recipes?") comes after a yes to that. "Save that recipe" works at any point. It's never saved without a yes.
